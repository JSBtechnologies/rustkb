# Editions, MSRV and modern Rust

Decides which edition and `rust-version` a crate declares, how to migrate, which legacy patterns
to replace with std, and which recent language/library features are safe to use. Read it when
creating a crate, bumping toolchains, or when code "looks 2019" (lazy_static, `Box<dyn Error>`
everywhere, `async-trait` on every trait). Stabilization versions below were checked against
`RELEASES.md`; the `rustkb` MCP tool `rust_release` returns the notes for any version.

## Edition and rust-version for new crates

### ED-01: New crates use edition 2024 and declare `rust-version`

**Default:** `edition = "2024"` plus an explicit `rust-version` in every `Cargo.toml` (or once in
`[workspace.package]` and inherited). **Never** generate `edition = "2021"` for a new project — it is
the most common stale default in LLM-written manifests. Edition 2024 needs Rust 1.85+.

```toml
[workspace.package]
edition = "2024"
rust-version = "1.85"      # the oldest toolchain you actually test (see ED-05)

# crates/foo/Cargo.toml
[package]
name = "foo"
version = "0.1.0"
edition.workspace = true
rust-version.workspace = true
```

Edition 2024 implies `resolver = "3"` for a package; a **virtual workspace** (no root `[package]`)
has no edition, so set `resolver = "3"` in `[workspace]` explicitly.

### ED-02: `rust-version` is a real contract — let tooling enforce it

**Default:** set `rust-version` and rely on what it switches on:

| Tool | Effect of `rust-version` |
|---|---|
| Cargo resolver v3 (1.84+, default in 2024) | Prefers dependency versions whose own `rust-version` is compatible (`incompatible-rust-versions = "fallback"`) |
| `cargo add` | Picks the newest dependency version compatible with your `rust-version` |
| Cargo build | Errors on an older toolchain instead of emitting confusing syntax errors |
| Clippy `incompatible_msrv` (warn by default) | Flags std APIs newer than `rust-version` |
| Clippy `msrv` | Defaults to `rust-version`; MSRV-sensitive lints only suggest APIs you can use |

**Never** set `rust-version` to a version you do not test — it then lies to the resolver and to
users. Raising `rust-version` is treated as a minor (not major) change by Cargo's guidance; say so
in the changelog.

## Choosing and testing an MSRV

### ED-03: Pick the MSRV by crate type

| Crate type | Default MSRV policy |
|---|---|
| Application / service / internal tool | Current stable; pin it in `rust-toolchain.toml` and bump deliberately |
| Library published to crates.io | A written policy, e.g. "latest stable minus 2" or "stable as of 6 months ago"; floor 1.85 if you want edition 2024 |
| Library needed by distro-packaged or embedded users | Whatever those users ship; consider staying on edition 2021 only if they are below 1.85 |

**Use** an older MSRV only for a named consumer. **Never** hold back an application's toolchain "for
compatibility" — nobody depends on it.

### ED-04: A feature is usable only if it is older than your MSRV

Before using an API or syntax from the timeline below, compare its version with `rust-version`.
Clippy's `incompatible_msrv` catches most std API mistakes, but **not** syntax (let chains, if-let
guards, `use<..>`) — those simply fail to compile on the old toolchain, which is why ED-05 exists.

### ED-05: Test the MSRV in CI

**Default:** one CI job runs `cargo +<msrv> check --workspace --all-features --locked` (or `cargo hack
check --rust-version --workspace`). A lockfile generated by resolver v3 already prefers compatible
versions, so this usually passes without `cargo update --precise` gymnastics. CI layout itself is
covered by `rust-architecture`.

## What edition 2024 changed

### ED-06: Write code the 2024 way

| 2024 change | What to write now |
|---|---|
| RPIT (`-> impl Trait`) captures all in-scope lifetimes | Drop `+ '_` / `Captures<'a>` tricks; opt **out** with `+ use<'a, T>` (1.82+) when the returned type must not borrow |
| `if let` scrutinee temporaries drop before `else` | A `lock()` guard in `if let ... = m.lock().unwrap().get()` is released before `else` (fixes a classic deadlock) |
| Tail-expression temporaries drop before locals | `let x = cell.borrow().len(); x` workarounds are no longer needed |
| `let` chains in `if`/`while` (1.88+, 2024 only) | `if let Some(x) = a && let Ok(y) = f(x) && y > 0 { .. }` instead of nested `if let` |
| `extern` blocks must be `unsafe extern` | `unsafe extern "C" { pub safe fn abs(x: i32) -> i32; }` — see `unsafe-ffi.md` |
| Unsafe attributes | `#[unsafe(no_mangle)]`, `#[unsafe(export_name = "..")]`, `#[unsafe(link_section = "..")]` |
| `unsafe_op_in_unsafe_fn` warns | Every unsafe op inside an `unsafe fn` needs its own `unsafe {}` block with a `// SAFETY:` comment |
| References to `static mut` are denied | Use atomics, `Mutex`, `LazyLock`/`OnceLock`, or `&raw const`/`&raw mut` |
| `std::env::set_var` / `remove_var` are `unsafe` | Set env before spawning threads, or pass config explicitly instead of mutating the environment |
| Never-type fallback is `!` (not `()`) | Annotate the type when an expression like `panic!()`/`return` feeds a generic (`f::<()>()`) |
| `expr` macro fragment also matches `const {}` and `_` | Use `$e:expr_2021` only if a macro relied on the old behaviour |
| `gen` is a reserved keyword | Rename identifiers called `gen`, or write `r#gen` |
| `#"foo"#` and `##` are reserved syntax | Add a space in macro input that used them |
| `Future`/`IntoFuture` in the prelude | Delete the `use std::future::Future;` lines; rename clashing trait methods |
| `Box<[T]>::into_iter()` yields `T` | Iterate a boxed slice by value directly |
| Match ergonomics reservations | Don't write `ref`/`mut`/`&` inside a pattern that is already matching through a reference |
| Cargo: `[project]`, `dev_dependencies` and other `snake_case` keys removed | Use `[package]`, `dev-dependencies`, `default-features`, `crate-type`, `proc-macro` |
| Rustdoc merges doctests into one binary | Doctests run much faster; a doctest that needs its own process (line numbers, globals) gets the `standalone_crate` code-block tag |
| rustfmt style edition 2024 | `cargo fmt` infers it from `edition`; set `style_edition = "2024"` in `rustfmt.toml` so plain `rustfmt` agrees |

### ED-07: Migrate editions with `cargo fix`, one crate at a time

**Default:** on a clean tree run `cargo update`, then `cargo fix --edition --all-targets
--all-features`, then change `edition = "2024"`, then `cargo build`/`cargo test`/`cargo fmt`. `cargo fix` rewrites
`extern` blocks, attributes, `gen` identifiers, and inserts conservative `match` rewrites for the
`if let` rescope — **review those rewrites**: most can be reverted to the simpler `if let`
because the new drop order is what you wanted. **Never** hand-edit the edition first and chase
compiler errors; you lose the automatic lint-driven fixes. In a workspace, migrate leaf crates first.

```rust
use std::sync::Mutex;

/// Edition 2024: the guard from `lock()` is dropped before the `else` branch runs,
/// so re-locking there no longer deadlocks.
pub fn get_or_insert(cache: &Mutex<Vec<u32>>, idx: usize) -> u32 {
    if let Some(v) = cache.lock().expect("cache mutex poisoned").get(idx).copied() {
        v
    } else {
        let mut guard = cache.lock().expect("cache mutex poisoned");
        guard.push(0);
        0
    }
}
```

## Replacing legacy crates and idioms with std

### ED-08: Replace legacy crates (lazy_static, once_cell, cfg-if, atty, num_cpus) with std

**Default:** if std covers it at your MSRV, use std and drop the dependency. Agents still emit
the left column from old training data.

| Legacy | Modern replacement | Since |
|---|---|---|
| `lazy_static!`, `once_cell::sync::Lazy` | `std::sync::LazyLock` (`LazyCell` for single-thread) | 1.80 |
| `once_cell::sync::OnceCell` | `std::sync::OnceLock` / `std::cell::OnceCell` | 1.70 |
| `crossbeam::scope`, `Arc` just to share with short-lived threads | `std::thread::scope` | 1.63 |
| `num_cpus::get()` | `std::thread::available_parallelism()` | 1.59 |
| `atty` | `std::io::IsTerminal` | 1.70 |
| `memoffset::offset_of!` | `core::mem::offset_of!` (nested fields 1.82) | 1.77 |
| `static_assertions::const_assert!` | `const { assert!(..) }` inline const | 1.79 |
| `async-trait` on traits used only generically | native `async fn` in traits (keep `async-trait`/`trait-variant` for `dyn`; see `async.md`) | 1.75 |
| `std::error::Error` in `no_std` via `std` feature | `core::error::Error` | 1.81 |
| `#[allow(lint)]` for known false positives | `#[expect(lint, reason = "..")]` | 1.81 |
| `ptr::addr_of!` / `addr_of_mut!` | `&raw const x` / `&raw mut x` | 1.82 |
| `Captures<'a>` trick / `+ '_` on RPIT | `impl Trait + use<'a>` (and nothing at all in 2024) | 1.82 |
| `itertools::repeat_n` | `std::iter::repeat_n` | 1.82 |
| `os_pipe` | `std::io::pipe` | 1.87 |
| `fs2` / `fs4` file locking | `File::lock` / `try_lock` / `lock_shared` | 1.89 |
| `cfg-if::cfg_if!` | `cfg_select!` | 1.95 |
| `assert!(matches!(..))` | `assert_matches!` (`use std::assert_matches;`) | 1.96 |
| `structopt` | `clap` 4 with `#[derive(Parser)]` | — |
| `failure`, `error-chain` | `thiserror` 2 (libraries) / `anyhow` (apps); see `error-handling.md` | — |
| `mem::uninitialized()` | `MaybeUninit` | 1.36 |
| `try!(..)`, `extern crate foo;` | `?`, plain `use` (edition 2018+) | — |

Crate-level choices (which JSON/HTTP/CLI crate) live in `rust-ecosystem`; `tier = "avoid"`
entries in its catalog list the crates above with their replacements.

```rust
use std::collections::HashMap;
use std::sync::LazyLock;

// ✅ std-only global: no lazy_static / once_cell dependency.
static UNITS: LazyLock<HashMap<&'static str, u64>> = LazyLock::new(|| {
    HashMap::from([("k", 1_000), ("m", 1_000_000), ("g", 1_000_000_000)])
});

pub fn parse_size(s: &str) -> Option<u64> {
    let split = s.find(|c: char| !c.is_ascii_digit())?;
    let (num, unit) = s.split_at(split);
    Some(num.parse::<u64>().ok()? * UNITS.get(unit)?)
}

const _: () = assert!(size_of::<u64>() == 8); // replaces static_assertions::const_assert!
```

## Recent stable features worth using

### ED-09: Use 1.80–1.96 features when your MSRV allows

**Default:** reach for these instead of the manual workaround. The version is the minimum
`rust-version` the code needs.

| Since | Feature | Replaces |
|---|---|---|
| 1.80 | `LazyLock`, `LazyCell`; exclusive range patterns `0..10 =>` | lazy_static; `0..=9` |
| 1.80 | `slice::split_at_checked`, `str::trim_ascii` | manual bounds checks |
| 1.81 | `#[expect(..)]`, `core::error::Error` | `#[allow]`, std-only errors |
| 1.82 | `Option::is_none_or`, `is_sorted*`, `iter::repeat_n`, `&raw`, `use<..>`, `unsafe extern` | `map_or(true, ..)`, windows checks |
| 1.83 | `Option::get_or_insert_default`, `Entry::insert_entry`, `&mut` in `const fn` | manual `match` |
| 1.84 | Strict-provenance pointer APIs; resolver v3 (MSRV-aware) | `as usize` pointer casts |
| 1.85 | Edition 2024; async closures (`async \|x\| ..`, `AsyncFn*` bounds) | `Fn() -> Fut` generics |
| 1.86 | Trait upcasting (`&dyn Sub` → `&dyn Super`); `get_disjoint_mut`; `Vec::pop_if`; `OnceLock::wait` | `as_any` methods; `split_at_mut` gymnastics |
| 1.87 | `Vec::extract_if`, `io::pipe`, `uN::is_multiple_of`, `use<..>` in trait RPITIT | `retain` + second pass |
| 1.88 | Let chains (2024 only); `HashMap::extract_if`; `Cell::update`; `cfg(true)` | nested `if let` |
| 1.89 | `File::lock`; `Result::flatten`; `_` for inferred const generic args | fs2, `and_then(identity)` |
| 1.90 | `lld` is the default linker on `x86_64-unknown-linux-gnu` | manual `-C link-arg` tweaks |
| 1.91 | `strict_*` integer ops (panic on overflow in release too); `Duration::from_mins/from_hours`; `BTreeMap::extract_if` | `checked_*().unwrap()` |
| 1.92 | `RwLockWriteGuard::downgrade` | drop + re-read |
| 1.93 | `fmt::from_fn`; `slice::as_array`; `VecDeque::pop_front_if` | ad-hoc `Display` wrapper structs |
| 1.94 | `slice::array_windows`; `LazyLock::get`; `Peekable::next_if_map` | `windows(2)` + indexing |
| 1.95 | `if let` guards in `match`; `cfg_select!`; `Vec::push_mut`; `Atomic*::update`; `hint::cold_path` | cfg-if, CAS loops |
| 1.96 | `assert_matches!` / `debug_assert_matches!`; `core::range::Range` (Copy range types) | `assert!(matches!(..))` |

Released after the toolchain this file was verified on (use only with `rust-version` ≥ that
release): 1.97 adds Cargo `build.warnings = "deny"` (replaces `RUSTFLAGS=-Dwarnings` in CI) and
integer `bit_width`/`highest_one`; 1.98 adds `bool::ok_or`, `str::strip_circumfix`.

```rust
use std::assert_matches;

#[derive(Debug)]
pub enum Cmd {
    Move { dx: i32, dy: i32 },
    Say(String),
}

pub fn parse(line: &str) -> Option<Cmd> {
    let (verb, rest) = line.split_once(' ')?;
    match verb {
        // if-let guard (1.95): bind inside the guard, no nested match.
        "say" if let Some(msg) = rest.strip_prefix('"').and_then(|r| r.strip_suffix('"')) => {
            Some(Cmd::Say(msg.to_owned()))
        }
        "move" => {
            // let chain (1.88, edition 2024): flat instead of nested if-let pyramid.
            if let Some((x, y)) = rest.split_once(',')
                && let Ok(dx) = x.trim().parse()
                && let Ok(dy) = y.trim().parse()
            {
                Some(Cmd::Move { dx, dy })
            } else {
                None
            }
        }
        _ => None,
    }
}

pub fn drain_negatives(v: &mut Vec<i32>) -> Vec<i32> {
    v.extract_if(.., |x| *x < 0).collect() // 1.87: remove-and-collect in one pass
}

pub fn swap_scores(scores: &mut [u32], a: usize, b: usize) -> bool {
    // 1.86: two &mut into one slice without split_at_mut arithmetic.
    let Ok([x, y]) = scores.get_disjoint_mut([a, b]) else { return false };
    std::mem::swap(x, y);
    true
}

#[test]
fn modern_features() {
    assert_matches!(parse("move 1, -2"), Some(Cmd::Move { dx: 1, dy: -2 }));
    assert_matches!(parse(r#"say "hi""#), Some(Cmd::Say(s)) if s == "hi");
    let mut v = vec![3, -1, 4, -5];
    assert_eq!(drain_negatives(&mut v), [-1, -5]);
    assert!(Some(3).is_none_or(|n| n > 2)); // 1.82
}
```

## Unstable features: do not emit them on stable

### ED-10: Never generate nightly-only syntax or `#![feature]` for a stable project

**Default:** target stable. These are **not** stable as of 1.98, yet appear in LLM output:

| Not stable | Write instead |
|---|---|
| `try { .. }` blocks | a helper fn or closure returning `Result`, then `?` |
| `gen { .. }` blocks / `gen fn`, `yield` | `std::iter::from_fn`, a hand-written `Iterator`, or `async-stream` style crates |
| `!` as a type outside `fn f() -> !` | `std::convert::Infallible` |
| `type Foo = impl Trait;` (TAIT) / `impl Trait` in associated types | name the concrete type, box it, or return `impl Trait` from a fn |
| Return-type notation `T::method(..): Send` | `trait_variant::make(Send)` or explicit `-> impl Future<Output = _> + Send` (see `async.md`) |
| `async fn` in `dyn Trait` | `async-trait` or a manually boxed future |
| `specialization`, `const trait impl` | separate traits / macros |
| `#![feature(..)]` anything | not on stable; only use with a pinned nightly and a stated reason |

`rustc` rejects these with `E0658`; the fix is to rewrite, never to switch the project to nightly.

## Review checklist

- [ ] `edition = "2024"` and `rust-version` set (inherited from `[workspace.package]` in workspaces) — ED-01
- [ ] Virtual workspace root sets `resolver = "3"` — ED-01
- [ ] `rust-version` is tested by a CI job on that exact toolchain — ED-02, ED-05
- [ ] No API/syntax newer than `rust-version` (clippy `incompatible_msrv` clean) — ED-04
- [ ] No `static mut` references, no bare `extern "C" {}`, no `#[no_mangle]` without `unsafe(..)` — ED-06
- [ ] Edition migration done via `cargo fix --edition`, conservative `match` rewrites reviewed — ED-07
- [ ] No `lazy_static`/`once_cell`/`atty`/`num_cpus`/`memoffset`/`cfg-if` where std suffices — ED-08
- [ ] Nested `if let` pyramids replaced by let chains / if-let guards when MSRV ≥ 1.88 / 1.95 — ED-09
- [ ] No `#![feature]`, `try {}`, `gen {}`, TAIT or RTN in stable code — ED-10
